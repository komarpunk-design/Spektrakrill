# Ускорение Lab-конвейера — 9.75

Движок остаётся C++/Vulkan. Изменения ускоряют существующие операторы, не меняя набор инструментов, разрешение, диапазоны параметров или исходные таблицы материалов и сканеров.

## Реализовано

### Layered Transport на CPU

Свёртки и восстановление масштаба теперь распределяются по потокам с учётом числа пикселей и размера ядра. Прежний планировщик оценивал только количество строк: обычный предпросмотр не достигал порога параллельного запуска. Порядок суммирования внутри каждого пикселя сохранён.

### Заводской Noritsu на CPU

Независимые строки стадий RGB→YCC, Auto Contrast, Film Sharp, коррекции, Hue/Saturation и обратного преобразования обрабатываются параллельно. Упаковка float→u16 и обратная распаковка остаются последовательными: они используют одну память, поэтому параллельная запись повредила бы соседние исходные значения. Таблицы, округления, целочисленные операции и правила float32 сохранены.

### Совместимые GPU-стадии предпросмотра

Наличие Lab JSON больше не отключает сразу все индивидуальные GPU-операторы в предпросмотре. Каждый оператор продолжает проверять собственную совместимость: Arctic exposure, Layered Transport и химия Langmuir остаются на соответствующих CPU-путях; совместимые вычисления кривых и диффузии могут использовать существующие Vulkan-ядра.

Для Lab-экспорта ограничение на GPU-стадии плёнки сохранено. Ограничения объединённого GPU-конвейера и полосовой обработки также сохранены: некоторые Lab-операторы требуют статистики всего изображения. Эта версия не заявляет полный перенос всех моделей на GPU.

### Спектральное считывание виртуального сканера

Существующий Vulkan-шейдер спектрального интеграла теперь доступен для виртуального LED-приёмника в Digital Reference, Auto Levels, Lab Scan, Noritsu и Nikon. В него передаются те же 81 спектральный отсчёт красителей, основы и LED-весов. Последующая калибровка, инверсия, матрицы сканера, тон и гамут работают прежними алгоритмами. Промежуточная энергия использует уже выделенный выходной буфер, без дополнительного полноразмерного host-растра.

Защита ускоренного пути:

- минимум 4096 пикселей, правильная форма спектральных таблиц, отдельные входной и выходной буферы;
- проверка конечности всех входных плотностей и их принадлежности проверенному диапазону;
- для каждого набора коэффициентов проверка Vulkan-результата на 343 образцах плотностей против исходной double-модели;
- дополнительная проверка около 64 образцов каждого кадра; допуск в log10 энергии — 0.00002;
- при несовместимости, ошибке GPU или нарушении допуска весь проход пересчитывается исходным CPU-оператором.

Это ускоренный float32-путь, а не обещание побитового совпадения GPU и CPU. При выключенном ускорении используется исходный CPU-расчёт. Диагностическая переменная `SPK_RECEIVER_GPU=0` отключает только новый интеграл, сохраняя тот же Fast-режим зерна для корректного сравнения. В Android logcat `Spektra / LED receiver` указывает использование GPU или причину отказа; время и объём пересылок включены в существующую статистику стадий.

### Изоляция кешей

Ключи промежуточных кешей плёнки и печати теперь учитывают фактический запрос GPU. Быстрый предпросмотр не может передать приближённый промежуточный результат последующему точному CPU-расчёту. Повторное использование внутри одного режима сохранено.

## Выполненные проверки

- 1529 Android unit-тестов редактора и 32 теста RAW-модуля: без ошибок.
- Исходный oracle Noritsu: 5 заданий × 6 стадий и 5 полных цепочек, с одним и четырьмя потоками.
- Побитовое совпадение CPU при 1/4 потоках для Layered Transport и Noritsu, включая нечётные размеры 513×385; существующий `test_parallel` также прошёл.
- 36 GPU/CPU сравнений приёмников: 6 моделей, автонастройка on/off, sRGB/Adobe RGB/ProPhoto. Новая проверка требует реально выполненного GPU-прохода, а не успешного CPU fallback. Неподдерживаемая плотность проверена на побитовый CPU fallback.
- 8 полных цепочек Arctic + Layered Transport + Langmuir + RMS + Nikon/заводской Noritsu, с зерном on/off, предпросмотром и Fast-экспортом. При сравнении экспорта сохраняется одна реализация зерна. Максимальная разница финальных каналов: около 0.00021 для Nikon и 0.00561 для Noritsu; максимальный RMS — 0.000054. Квантование заводских стадий может усиливать малую разницу на входе.
- После GPU-предпросмотра точный CPU-результат побитово совпал с холодным CPU-расчётом на маршрутах скана и фотобумаги.
- 224 проверки preview/export с CPU backend; проверки скан-воркстейшена, настоящего негатива, нейтральной шкалы Nikon, гамутов, Film First, заводского Noritsu и исходные `test_simulate_e2e` goldens: пройдены.
- Итоговый ARM64 release APK собран; подпись соответствует предыдущей версии, проверены ZIP CRC и выравнивание библиотек для 16 KiB страниц.

Vulkan-проверки выполнены через настоящий Vulkan API с **программным драйвером Mesa Lavapipe на Linux**. Физический Android/GPU недоступен. Эти проверки подтверждают исполнение шейдера и численное согласование в этой среде, но не доказывают производительность или корректность конкретного драйвера телефона. Встроенные численные проверки остаются обязательными на устройстве.

Отдельный замер после завершения сборок, один запуск на облачном CPU: Layered Transport 512×384 — 5052 мс при одном потоке и 2121 мс при четырёх; Noritsu 512×384 — 502 и 274 мс, 513×385 — 510 и 294 мс. Выходные значения совпали побитово. Это время отдельных операторов в этой среде, а не прогноз ускорения всего приложения на телефоне.

## Воспроизведение host-проверок

Обычная сборка: `cmake -S tests/native-upstream -B /tmp/spk-host`, затем `cmake --build /tmp/spk-host -j3`.

Для Vulkan добавляются `-DSPK_HOST_VULKAN=ON`, путь к заголовкам Vulkan через `SPK_VULKAN_INCLUDE_DIR` и библиотеке через `SPK_VULKAN_LIBRARY`. Рабочий каталог — корень репозитория. ICD выбирается обычным `VK_ICD_FILENAMES`.

```sh
/tmp/spk-host/lab_acceleration_probe native-android/engine/spektra-core/src/main/assets/spektra --gpu
/tmp/spk-host/lab_gpu_pipeline_probe native-android/engine/spektra-core/src/main/assets/spektra
/tmp/spk-host/lab_parallel_probe
```

Первые две команды требуют доступного Vulkan-устройства. Для проверки CPU fallback первая запускается без `--gpu`; вторая намеренно завершается ошибкой без Vulkan. Показатели времени в `lab_parallel_probe` относятся только к двум конкретным CPU-операторам, не ко всему приложению и не к телефону.
