# Профильные стадии Noritsu · 9.67

19 ноября 2026, Москва. Android 7+, ARM64, versionCode 137.

**В APK есть рабочие ядра и импорт профиля, но нет готовой калибровки задания.**
В публичном noritsu-tool опубликованы алгоритмы и контрольные хеши проверочного
PCB/COM-комплекта, а не сам комплект. Нельзя включить эти три блока без необходимых
данных. Обычный Noritsu 9.66 и все его ручные поправки продолжают работать сразу.
Тестовые таблицы не используются как замена измеренной калибровки.

## Расположение

**Скан → Скан без бумаги → Noritsu LS-600 · реконструкция →
Профильные стадии Noritsu**. Это одна раскрываемая группа рядом с градацией,
цветом и детализацией; рабочая навигация и основной Material UI сохранены.

1. «Импортировать профиль задания» открывает системный выбор JSON.
2. После проверки видны имя, происхождение, разрядность, кодирование и SHA-256
   исходного блока. Импорт не включает обработку автоматически.
3. «Цветовой тракт RGB ↔ YCC» включает преобразования из задания.
4. Local Auto Contrast, Film Sharp и Hue/Saturation S0 включаются независимо,
   если в комплекте есть соответствующие исходные данные. Причина недоступности
   подписана рядом с названием. Неработающие переключатели не показываются.
5. Экспорт профиля сохраняет JSON, повторно читает файл и проверяет его целиком.
   «Отключить профильные стадии» и общий сброс скана сохраняют импортированный
   комплект, чтобы его не приходилось загружать заново.

Все переключатели, профиль и обычные числовые поправки входят в рецепт,
пресеты и историю. Импорт валидируется до атомарной записи состояния.

## Связь с остальным движком

Вход — коды плотности настоящей перенесённой FilmLUT из существующего
виртуального спектрального приёмника. Положительное изображение не переводится
назад в якобы аппаратный RAW. Последовательность:

`приёмник → FilmLUT → RGB/YCC S1 → [Auto Contrast] → [Film Sharp] →
YCC correction → [Hue/Saturation] → YCC/RGB + gamma → операторские EV/CMY/RGB,
градация/насыщенность → прежние общие тон/уровни → оптика → выходное пространство`.

- Профиль обходит прежний автоподбор адаптера. Значение автоподбора сохраняется.
- EV и CMY при этом применяются после профильного вывода. Подпись в UI меняется.
- Film Sharp заменяет обычную нерезкую маску на время своего включения.
  Значения USM не стираются; размытие оптики остаётся отдельным инструментом.
- Lab Scan, Digital Reference, Auto Levels и бумажный вывод не получают новых
  стадий. Сохранённые неактивные настройки объяснены в UI.
- Для ч/б сохранён Digital Reference fallback, для слайда — прямой вывод.
- Маршрут настоящего негатива использует те же стадии после своего приёмника;
  калибровка/маска настоящего негатива остаются в отдельной странице.
- RGB-буфер уплотняется в uint16 на месте; Film Sharp считается полосами с
  перекрытием и неизменяемой исходной яркостью. Дополнительный полный RGB-кадр
  для пространственных стадий не выделяется.
- Файл профиля ограничен 512 КиБ; обычный большой рецепт без объекта задания
  не обходит прежний нативный лимит 16 КиБ. Ограничения глубины, числа узлов,
  длины строк и массивов JSON-парсера не увеличены.

## Подготовка реального комплекта

Нужны легально полученные согласованные **final PCB** (ровно `0x1493e` байт)
и, для Hue/Saturation, исходная решётка COM (58806 байт). Поддерживается
RGB/YCC S1, YCC correction и variant-1 YCC/RGB; другие селекторы отклоняются.
Кодирование gamma-выхода и разрядность объявляются явно, по реальному заданию.

```sh
python native-android/tools/noritsu/pack_job.py \
  --pcb /path/to/final.pcb --lattice /path/to/hue-lattice.bin \
  --encoding srgb --output-bits 16 --name 'Моё задание' \
  --output Noritsu-job.json
```

Требуется NumPy. Пакетировщик использует исходные декодеры и построители таблиц,
проверяет хеши сохранённых исходников, не генерирует отсутствующую калибровку.
Без `--lattice` Hue/Saturation недоступен. Неактивные source-стадии не
подставляются. Hex разбит на строки до 4096 символов под существующий парсер.

## Проверка и границы достоверности

- Независимый oracle вызывает неизменённые исходные Python-функции: 30 стадий
  сравниваются побитно в uint16; 5 полных цепочек — с точностью float32.
  Проверяются разные насыщенности, коэффициенты уменьшения, нечётные размеры,
  ядра и границы полос Film Sharp. Все профили **синтетические, тестовые**.
- Пакетировщик проверяется синтетическим PCB/COM через оригинальные декодеры
  в обеих разрядностях, с решёткой и без неё; неподдерживаемый селектор отвергается.
- Полный настоящий C++-движок проверяется на цветных плёнках, пяти выходных
  пространствах, маршруте негатива, несовместимых режимах и обходе USM.
- Старые результаты сравниваются с зафиксированными буферами 9.66, а UI,
  импорт/экспорт пресетов, зависимости, сброс и восстановление — Android-тестами.
- Снимки экрана сделаны Robolectric с тестовой серой областью предпросмотра.
  Это проверка реальной Compose-навигации на 320dp, не тест на физическом телефоне
  и не пользовательское исследование.

Фактически пройдены: **1475 Android-тестов приложения + 32 RAW-теста**,
30 изолированных стадий + 5 полных исходных цепочек (включая gamma 8/16 бит
и адаптер sRGB/linear), 42 полные обработки профильного маршрута и по 42 для
8-/16-битного результата пакетировщика, 90 прежних Noritsu-обработок,
192 прежних сравнения предпросмотра/экспорта без расхождений. Все 24 буфера
со стандартными настройками побитно совпали с сохранённой 9.66.
ASan/UBSan прошли на этих новых стадиях; LeakSanitizer не запускался из-за
ограничений окружения. Oracle использует исходные Python-функции, а не вторую
переписанную реализацию тех же формул в тестах.

Совпадение с физическим Noritsu не заявляется. Наш спектральный приёмник
отличается от CCD-входа, а переносимость задания на произвольный виртуальный
кадр не измерена. Пространственные параметры заданы в пикселях конкретного
задания: сравнение предпросмотра с экспортом подтверждено при одинаковом
разрешении; масштабная эквивалентность при разных разрешениях не подтверждена.
Имеющийся комплект может быть неприменим к слишком маленькому изображению;
движок возвращает причину вместо молчаливой подмены алгоритма.

Успешный форматный импорт означает совместимость структуры, а не подлинность
калибровки. `sourceSha256` и `latticeSha256` — сведения о происхождении: без
исходного PCB/COM приложение не может повторно доказать их соответствие данным.
Синтетическая тестовая калибровка не попадает в production assets/APK.
