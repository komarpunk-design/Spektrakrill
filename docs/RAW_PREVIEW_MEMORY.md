# RAW больше 24 МиПикселей: память предпросмотра · 9.61

## Воспроизведённая причина

Скриншот 9.60 показал `NO_MEMORY (7), LibRaw: 0` с текстом
`RAW geometry exceeds 24 MiPixel in-memory safety limit for available device RAM`.
Это предварительный отказ ограничения геометрии, а не установленный факт ошибки
`malloc` или повреждения файла. Обработка прекращена на проверке допустимых размеров.

Обычный предпросмотр всегда передавал `admittedBytes = 0` и зависел от грубых
порогов 12/24/32/64 МиПикселя. Экспорт уже умел резервировать конкретное количество
свободных байтов и передавать его нативному декодеру. Поэтому файл мог подходить
по фактическому бюджету, но предпросмотр сразу переходил на системную картинку.

На CC0 RAW Fujifilm X-T3 из raw.pixls.us #2783 воспроизведён тот же отказ 24 МиПикселя.
С резервом 768 МиБ тот же нативный декодер читает его как RAW, через fd и buffer,
с побайтово одинаковыми линейными ProPhoto RGB прокси. Название камеры пользователя
и его оригинальный RAW не получены; X-T3 — воспроизводящий файл, а не утверждение
о том, какой камерой снят его кадр.

## Что изменено

Обычное нативное чтение предпросмотра сохранено. Только после `NO_MEMORY`:

1. Освобождаются простаивающие GPU-буферы и запрашивается сборка мусора.
2. Заново измеряется свободная память Android и процессный MemoryBudget.
3. Резервируется не больше `min(availMem − threshold − 256 МиБ, budgetFree)`.
4. При наличии резерва от 336 МиБ выполняется ровно одна новая попытка LibRaw.
5. Резерв освобождается при успехе, ошибке или отмене. Причина первого отказа
   сохраняется в suppressed-ошибке повторного отказа для диагностики.

Резерв используется той же существующей политикой, что и экспорт: нативный
декодер рассчитывает допустимую геометрию из измеренной оценки 28 байт/пиксель.
Размер выдаваемого предпросмотра остаётся ограничен его исходным `maxEdge`.
Без достаточного резерва увеличенная попытка не выполняется. Повреждённые файлы,
неподдерживаемые метаданные и отмена не запускают эту процедуру.

Глобальные лимиты, C++/LibRaw, обработка пикселей и правила полного RAW-экспорта
не изменялись. При действительной нехватке памяти остаётся запасной предпросмотр;
его предупреждение теперь отличает отказ бюджета геометрии от ошибки выделения
памяти. 9.61 не обещает прочитать любой RAW на любом объёме свободной памяти.

## Проверка

- 1427 app unit/Robolectric тестов: обычное чтение без лишней повторной попытки,
  воспроизведение отказа 24 МиПикселя, удержание/освобождение резерва, отмена,
  недостаточный бюджет, остановка после второго отказа и другие статусы декодера.
- Новый опциональный native-тест `sfraw_camera_preview_memory_test` работает
  с настоящим X-T3 RAF, проверяет исходный отказ, нативное восстановление,
  точность 16-битного этапа, размер прокси, конечность/непостоянство float RGB,
  идентичность fd/buffer и полное сенсорное разрешение без подстановки превью.
- Существующие native resource-limit тесты проверяют сохранность ограничений.
- Выполнена Android release-сборка; результаты APK/JNI-проверок — в release notes.

SHA-256 исходного RAF:
`95b33021160b239ceb1a09d46a1b29cb60cb7dd47581feb126b337c219091754`.
URL — в RAW_CAMERA_TEST_FILES.json. Фотография не включается в репозиторий/APK.

Для воспроизведения при настроенном LibRaw host build:

```sh
cmake -S native-android/lib/libraw/src/test/host -B /path/to/host-build \
  -DSFRAW_CAMERA_ADMISSION_SAMPLE=/path/to/2783.RAF
cmake --build /path/to/host-build --target sfraw_camera_preview_memory_test
/path/to/host-build/sfraw_camera_preview_memory_test /path/to/2783.RAF
```

CMake проверяет SHA-256 опционального файла. На физическом устройстве пользователя
эта среда не запускает приложение; окончательная проверка его кадра остаётся за ним.
