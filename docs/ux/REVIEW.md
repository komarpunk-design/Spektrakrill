# Сценарии и самопроверка

Это экспертная оценка и автоматизированные проверки, не наблюдение за настоящими пользователями. Не проводилось независимое пользовательское исследование.

| Сценарий | Проверка / путь | Память и контекст | Восстановление |
|---|---|---|---|
| А: открыть, изменить, сохранить | Открыть → выбор файла → вкладка → значение → применить → экспорт (без обязательного мастера). Браузер реально скачивает JPEG. | Фото остаётся в рабочей области. Знакомые вкладки сохранены. | Ctrl Z / кнопка отмены. |
| Б: неизвестно, где параметр | Поиск → запрос → результат: 3 действия до раздела. Каталог перечисляет технические параметры и назначения. | Запоминать вкладку не обязательно. При доступном параметре группа раскрывается и поле подсвечивается. | Если параметр зависит от эффекта, указывается зависимость; для Layered Transport назван конкретный переключатель. |
| В: много связанных правок | Свободные вкладки и поиск; числовое значение → ввод → применить. | Нет переключения простого/профессионального режима. Изменённые значения помечены, каталог фильтрует изменённые разделы. | Неприменимые контролы имеют прежние причины/отключение, данные не нормализуются при переходе. |
| Г: нестандартные комбинации | Ввод проверяет диапазон, сохраняет шаг, поддерживает отрицательные числа и запятую. | Допустимые диапазоны не уменьшены; возвращены ранее hidden-advanced параметры. | Индивидуальное заводское значение при известном соответствии, Undo и отмена ввода. |
| Д: возвращение | Сохранение параметров и рецептов сохраняется; изменённые разделы находятся фильтром. | Это восстановление настроек, не доказательство восстановления исходного RAW после уничтожения Android-процесса. | Холодное восстановление самого файла остаётся ограничением существующей системы, см. ниже. |

## Подтверждённые проблемы и исправления

1. Глобальный advanced скрывал функции без указания их существования — в обработке все параметры доступны, глобальный «профессиональный» фильтр удалён.
2. Касание ползунка ставило минимум — обычное касание теперь не меняет параметр; перемещение и клавиатурный Home остаются явными действиями.
3. Точное значение нельзя было ввести — единый числовой редактор у SliderRow.
4. Индивидуальный сброс отсутствовал — заводское значение доступно в редакторе там, где доказано соответствие ключу; профильные значения не выдаются за универсальные.
5. Значения отображались без признака изменения — индикатор отличия от установленного заводского значения.
6. Редкие параметры находились только через знание вкладки — единый каталог названий, задач и динамических контролов.
7. Перенесённые источники имели перекрывающиеся устаревшие страницы — дублирующие алиасы не показываются в каталоге; Fotufilm и Negs остаются отдельными.
8. Числовой ввод мог бы принять мусор, пустую строку, бесконечность или выход за диапазон — валидация до изменения состояния, сообщение ошибки, сохранение прежнего значения.
9. Новый числовой элемент не принимал касание из-за pointer-events:none старого заголовка — воспроизведено Playwright, исправлено в CSS.
10. Три длинных семейства на странице плёнки перегружали инспектор — одноуровневые группы зерна/галяции/DIR, открываемые также поиском.
11. Технические объяснения были доступны только через настройку приложения — локальное раскрытие «Что делает…?» непосредственно у параметра.
12. Диалоги не имели доступного имени — добавлены имена, native modal focus handling и Escape/cancel.

## Границы проверки и оставшиеся риски

- Нет физического Android-устройства/пользовательской панели: TalkBack, системный Back, IME/insets, большой системный шрифт и длительная работа на слабом устройстве не подтверждены браузерным тестом.
- Значение по умолчанию для динамических/профильных контролов нельзя надёжно вывести только из label. Для известных helpers добавлена явная передача; для остальных редактор честно сообщает зависимость от профиля. Универсальный сброс каждого произвольного параметра пока не доказан.
- Поиск открывает и подсвечивает доступный контрол; условно не смонтированный параметр требует включения эффекта. Не все специфические причины автоматически распознаются: сохраняется контекстное сообщение и описание в разделе.
- Состояние параметров сохраняется, но холодное восстановление исходного RAW/разрешения URI после уничтожения Android-процесса не реализовано этим изменением.
- Нельзя заявлять совпадение браузера и Android по обработанным пикселям: существующие движки отличаются. Их прежние ограничения и нативные regression probes сохранены. Native preview/export parity на реальном устройстве отдельно не подтверждена.
- Частота действий, удобство групп и словарь поиска — гипотезы до наблюдений за пользователями. Требуется пользовательский тест A–Д.

Дополнительные исправления после прогона: Escape в поле поиска сначала поглощался стандартным search-input и оставлял каталог открытым — добавлен обработчик закрытия на уровне dialog; существовавший сброс вкладки удержанием её иконки убран из навигации, явная кнопка сброса сохранена. Для отрицательных значений добавлена кнопка смены знака: наличие минуса на Android decimal-клавиатуре не предполагается.

Фактический автоматизированный результат: 234 объявления контролов (включая 92 SliderRow, переключатели, поля, варианты Select и динамические вызовы) сохранены по именам/диапазонам/шагам/значениям/callbacks относительно 4821309; тест UX проходит ввод 1,25, отклонение 999999, заводской сброс и Undo, обычное касание без изменения, поиск «толщина» и динамических донорных параметров, Escape, геометрию 360/390/844/1440 и загрузку JPEG с сигнатурой FF D8. Технические suite transport/outputs/Negs/experimental проходят; это не доказательство пользовательского удобства.

13. Квантование считалось от нуля, поэтому LUT 9…33 с шагом 4 не сохранял заводское 17. Единый расчёт для ползунка/клавиатуры/ввода теперь отсчитывает шаг от объявленного минимума. Диапазон и шаг не менялись; отдельный тест проверяет все семь значений LUT, дробные и отрицательные значения.
14. Доступная подсказка ползунка не учитывала контекст раздела; исправлена связь aria-describedby и id. Тап-зоны нового значения и раскрытия подсказки увеличены до 44 px.

Дополнительно браузером проверены смена знака, восстановление EV после перезагрузки и прямое открытие/подсветка EV через поиск.

15. Индексатор принимал helper-переменную label за имя, пропускал строки Outputs и направлял часть контролов отрицательного скана в Спектр. Исправлен генератор по исходному Git-коммиту: 224 разрешённых строк, реальные mode-ветви, динамические и условные названия. Добавлены data-control-label и фокус переключателей/списков; переходы проверены для источника негатива, Layered Transport и Lab Scan.
16. Названия в подсказках «Плёнки»/«Бумага» расходились с реальными «Плёнка»/«Печать» — приведены в соответствие. Поиск теперь учитывает ё/е, несколько слов и русские «пуш/пул», «лейеры транспорт».

Дополнительно проверены отрицательное EV, перезагрузка, поиск «пуш», список источника негатива, включение Layered Transport, толщина основы, режим Lab Scan и ввод 0,55, сброс LUT к 17 и шаг клавиатурой до 21, фильтр изменённых разделов. Снимки реального браузерного прогона сохранены локально: artifacts/ux-workspace-photo-360.png, ux-number-360.png, ux-directory-360.png и геометрия 360/844/1440. Изображение в рабочем пространстве загружено, JPEG действительно скачан. Проверки на физическом устройстве остаются обязательной следующей валидацией перед снятием статуса экспериментальной версии.

17. Некоторые списки внутри Field не имели программного имени, хотя визуальная подпись была видна. Общий контекст Field теперь передаёт подпись Select при отсутствии явно заданного ariaLabel; поиск переводит фокус на именованный список.

19. Рамки не находились по поисковому слову «рамка» в описании Кадра, а дата на кромке была только обычным input вне индекса. Расширены назначение раздела и инвентарь текстовых полей/выбора рамки; прямой поиск даты, DX и рамки проверяется сценарием.
