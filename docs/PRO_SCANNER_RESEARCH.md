# Проверка реальных профессиональных сканеров

14 ноября 2026, Москва. Цель — найти подтверждённую модель для обработки
виртуального негатива Spektrafilm, не переименовывать существующий Lab Scan.
Код приложения и APK 9.64 этой проверкой не изменены.

## Noritsu LS-600 / EZ Controller 6.5

Исследован [negative-universal, commit 9c9298644c21baa0f086778ff64e0515c9207c63](https://github.com/rohanpandula/negative-universal/tree/9c9298644c21baa0f086778ff64e0515c9207c63/noritsu-tool).
В репозитории есть восстановленные целочисленные стадии и извлечённые
числовые таблицы оригинального RD5X. Модуль `noritsu/vendor.py` прямо
отделяет точные ядра от параметров, поступающих от аппарата или задания
EZ Controller. Это реальная и полезная основа для частичной интеграции.

Но `noritsu/pipeline.py` прямо обозначен как «Illustrative C-41 negative ->
positive pipeline», а не полная реконструкция. В нём применяются
нормализация плотностей, подобранный баланс и синтетическая тональная кривая
либо отдельная исходная таблица. Назвать этот режим полной эмуляцией LS-600
нельзя на основании наличия настоящей таблицы.

Полный regression `test_real_pair.py` требует внешний canonical evidence
bundle: исходный FULL RAW, машинный TIFF, PRM, финальный PCB, oracle,
цветовую lattice, описание изображения, геометрию и настройки. Эти данные
не находятся в проверенном публичном дереве. Обычный запуск пропускает
проверку при их отсутствии. Свои сравнения с настоящим LS-600 мы не проводили.

## Nikon Super Coolscan 5000 ED

Исследован [cool-colors, commit 74ffceb79e6e976858d9bffddfeefddba626378f](https://github.com/rohanpandula/cool-colors/tree/74ffceb79e6e976858d9bffddfeefddba626378f).
Реализован восстановленный CMS-off/CMS-on тракт. Фиксированные таблицы
CML4 и подтверждение совпадения захваченных цветовых событий опубликованы.

Точный режим требует неизменённых 16-битных device-RGB сканов Nikon и трёх
канальных builder-LUT именно от соответствующих prescan/exposure/film-mode
и экземпляра/сеанса сканирования. Автоматическое построение таких builder
для нового кадра в этом CLI ещё не опубликовано. Сам README предостерегает
от переноса builder даже между соседними кадрами.

Виртуальный негатив Spektrafilm и обычный камерный RAW не являются
таким Nikon device-RGB входом. Применение к ним найденных таблиц без
подтверждённого входного преобразования не даёт оснований заявлять
точную модель LS-5000. Опубликованную отдельную проверку CML4 не следует
выдавать за нашу проверку всей сканирующей цепочки.

## Hasselblad / Imacon Flextight

[flexcolor-tool](https://github.com/rohanpandula/flexcolor-tool) описывает
парсер профилей и частично восстановленную математику. README прямо
отмечает незавершённую проверку B-spline/gradation и полного
engine-equivalent rendering; сами оригинальные файлы профилей не
распространяются в проекте. Отдельно найденный ICC Flextight X5 — это
входная цветовая характеризация сканов, не готовая модель сканера для
виртуального негатива.

## Kodak/Pakon F135 / F235

Дополнительно проверен [pakon-reference, commit 76d9cd0a38f523398c3a19392070539ee80b75cf](https://github.com/alibosworth/pakon-reference/tree/76d9cd0a38f523398c3a19392070539ee80b75cf),
включая `docs/color-pipeline.md`. Это аппаратно подтверждённая документация,
не готовый движок. Формула `3500 * log10(16383/x)` подтверждена как перевод
в плотность, а не полный рендер позитива. Таблично-матричная цепочка относится
к F235; F135/F135+ используют другой, индивидуально калиброванный полином.
Документ прямо отмечает незавершённость описания 135-го цветового тракта и
полной реализации OEM matrix path вне родного ПО. Использовать матрицу F235
под названием F135 было бы неверно. В опубликованном справочнике достаточной
модели для нашего виртуального входа также не обнаружено.

## Вывод для интеграции

- Можно встроить конкретные восстановленные стадии Noritsu/Nikon с точным
  указанием их происхождения, входного контракта и ограничений. Это
  частичная реконструкция, а не доказанно полный аппарат.
- Для подтверждённой эмуляции из виртуального негатива необходимы также
  достоверная характеристика входного приёмника и согласованная калибровка;
  нужны эталоны для проверки всей цепочки. В изученных источниках
  достаточного комплекта для нашего входа не обнаружено.
- Это результат проверки перечисленных источников, не утверждение, что
  подходящих измерений или реализаций нигде не существует.
- Новая надпись с названием устройства поверх прежней обработки не
  реализована. Новый APK без функционального изменения не выпускался.

## Реализация после исследования

17 ноября добавлена согласованная частичная реконструкция табличных стадий
Noritsu. Границы точных стадий, адаптер и проверки описаны в
[NORITSU_RECONSTRUCTION.md](NORITSU_RECONSTRUCTION.md). Выводы исследования
о невозможности заявлять полное аппаратное совпадение остаются в силе.
