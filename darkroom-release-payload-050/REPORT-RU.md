28 ноября 2026 года. Darkroom Mobile 0.5.0, ARM64, Android 8.0/API 26+.

# Результат: рабочая компоновка настольного darktable

Световой стол с настоящими миниатюрами и отбором; Тёмная комната с историей,
фотографией, инспектором и лентой кадров. Панели складываются на телефоне,
разделитель меняет их размеры. Каталог, экспорт, стили, сравнение, гистограмма
и все прежние редакторы сохранены. У инструмента в ⋮ доступны оригинальные
.dtpreset, копирование настроек и имя экземпляра; при сохранении .dtstyle
можно выбрать инструменты. Автоприменение импортированных пресетов не включается.

Это перенос рабочей схемы в Android UI. Полного соответствия всем возможностям
настольного приложения нет; конкретные границы перечислены в матрице ниже.

Проверки: по 340 JVM/Compose-тестов Debug/Release, 39 Python-тестов runtime.
Реальный исходный движок/JNI на Linux: JPEG, Nikon D700 NEF, 26-МП Fujifilm RAF;
заводской .dtpreset меняет пиксели и сохраняет точные параметры, выбранный стиль
содержит один инструмент, собственный пресет несёт маску, его повторное применение
воспроизводит пиксели и сохраняет остальные экземпляры. Проверены копирование,
побайтовое равенство пикселей после переименования, исходная обработка и возврат
из сохранённой полной истории, а также native PNG-экспорт. PNG декодированы
независимо. Математика обработки, старые native-библиотеки и данные не менялись.

Подтверждённые проблемы, исправленные при проверке новой версии:

1. Прокрученные ползунки перехватывали физический тап по разделу: ограничена
   область и приоритет касаний закреплённой навигации.
2. Несколько сохранённых композиций использовали один ключ и могли падать:
   у выбранного экземпляра отдельное состояние, остальные свёрнуты.
3. Возвращение к инструменту теряло прокрутку: она хранится по категории/экземпляру.
4. Переход из каталога в редактор сбрасывал поиск и выделение: состояние каталога
   сохраняется отдельно; это проверяется реальным переключением Compose-экранов.
5. Русские названия групп разрывались посреди слова: убраны лишние отступы чипов.
6. Настройки нельзя было открыть до фотографии: добавлена доступная кнопка.
7. Системная RAW-миниатюра выглядела как результат обработки: добавлена «Исходник».
8. Одинаковый заводской/личный .dtpreset конфликтовал по ID: пространства разделены.
9. Перенос маски через стиль мигрировал исходный экземпляр: копирование opaque
   параметров выполняется через XMP; перед применением пресета миграцию делает
   оригинальный движок, затем проверяется независимость других экземпляров.
10. Сохранение старой строки могло пропустить свежие изменения общей маски:
    выбранные состояния подготавливаются в отдельном native-контексте.
11. Позиция истории 0 заставляла importer пересоздавать defaults и терять будущее:
    полный стек с курсором сохраняется отдельно до новой ветки обработки.
12. Из стиля могли молча выпадать image-specific pixel masks: используется
    оригинальная проверка переносимости с отказом вместо потери данных.

13. Новый каталог мог перекрывать прогресс, ошибку RAW и повторную попытку:
    для этих состояний возвращён прежний экран восстановления; загрузка
    в каталоге показывает прогресс и отмену. Добавлен отдельный UI-тест.

Скриншоты показывают production Compose-компоненты под Robolectric SDK35,
с настоящим тестовым JPEG. Это не запуск APK на Android и не результаты
пользовательского тестирования. Реальное устройство/эмулятор недоступны:
Android JNI/SAF/IME, системный process death, расход памяти и скорость на телефоне
остаются непроверенными. На маленьком экране глубокие редакторы требуют прокрутки;
панель можно увеличить или скрыть. Базовое различие fast preview и HQ export
не менялось. Очередь не является фоновой службой; оставьте приложение открытым.

Подпись, ZIP CRC, 16-КБ выравнивание, 115 старых библиотек и 830 файлов данных
проверены отдельно. Android-исходники находятся в приложенном source.zip;
стандартные GitHub Source code archives относятся к репозиторию доставки
Spektrakrill. Основная ветка и прежние релизы не заменяются.


# Сравнение с настольным darktable: Darkroom Mobile 0.5.0

Эталон — исходники настольного darktable из закреплённой ревизии
`1c4eaea9df6dbe8336449ca297acbb0120d8e968`, на которой основан Android-порт
`ae4139bdf18a5c39f71c24f1fb3eab320c139cc9`.
Сравнивались код, форматы и рабочие сценарии. Это не визуальное тестирование
настольного GTK-приложения рядом с телефоном: Android-устройство не подключено.
Дополнительно скачан и реально запущен CLI официального стабильного
[darktable 5.6.2](https://github.com/darktable-org/darktable/releases/tag/release-5.6.2).
Его AppImage проверен по опубликованному GitHub SHA-256. Закреплённый движок
порта относится к development-ветке 5.8, а не к этому стабильному релизу.

## Что добавлено в 0.3.0

Меню **⋮** справа в верхней панели открывает фотографии, стили, историю,
снимки обработки, закрепление сравнения, гистограмму и обмен XMP. Регулировки
остаются в существующих функциональных разделах.

- **Мои фотографии**: отдельная постоянная копия оригинала для каждого проекта,
  native XMP, импортированные LUT/наложения/растровые файлы и миниатюра находятся
  в `filesDir/photo-projects`, а не во временном кэше. Оригинал у системного
  файлового провайдера не изменяется. Успешные native-изменения сохраняются
  перед обновлением предпросмотра. Последний проект открывается при новом запуске.
- **История и снимки обработки**: произвольный переход по доступным шагам
  текущего native Undo/Redo; именованные постоянные снимки настроек. Перед
  восстановлением или применением стиля сохраняется резервный снимок. Возврат
  к снимку открывает новую native-сессию: её Undo начинается заново. Это явно
  указано в интерфейсе; мобильный Undo-кольцевой буфер не выдаётся за XMP.
- **Импорт/экспорт XMP**: используется оригинальный сериализатор
  `dt_exif_xmp_write`, включая native-историю и рисованные маски. Импорт проверяет
  структуру darktable, корректность XML и запрещает DTD/внешние сущности. При
  неудачном восстановлении прежний XMP возвращается. Максимум входного XMP —
  16 МиБ; проверка не обрезает файл незаметно.
- **Стили darktable**: настоящие `.dtstyle` импортируются побайтово, каталог
  ищет по названию, описанию и инструментам. Можно создать стиль из текущей
  обработки и экспортировать его. Применение вызывает исходный движок стилей
  с выбором добавления или замены обработки; по умолчанию — добавление.
  Файлы одного имени с разным содержимым не перезаписывают друг друга.
  Известные недоступные в текущем RAW/RGB-маршруте инструменты блокируют
  применение вместо молчаливого удаления частей стиля.
  Из штатного runtime подключены все **534 встроенных стиля**: 24 примера и
  510 стилей камер. Фильтры «Мои / Примеры / Камеры / Все» отделяют их без
  вложенного дерева. Названия `_l10n_` переводятся оригинальным MO-каталогом
  только при отображении; native-имена и содержимое файлов не меняются.
  Стили камер — настройки обработки, не профили декодирования RAW.
  Все 534 файла также побайтово совпадают с банком официального desktop 5.6.2.
- **Закреплённое сравнение**: постоянный PNG текущего предпросмотра, переключение
  между ним и новым результатом. Оно не создаёт edits и не меняет экспорт.
  Координатные режимы масок/тона выключают сравнение, чтобы тап нельзя было
  применить по геометрии другого состояния. Кнопки сравнения и Fit разнесены.
- **RGB-гистограмма**: реальные 8-битные каналы отображаемого предпросмотра,
  линейный/логарифмический масштаб и доля пикселей с каналом 0/255. Она не
  называется RAW-гистограммой или индикатором клиппинга сенсора. При недостатке
  высоты предлагается развернуть фото вместо схлопывания рабочей области.

Настройки из XMP и стилей обрабатываются штатным движком; новая библиотека
`libdarkroom_desktop.so` — небольшой JNI-мост к публичным C API. Она не содержит
собственных алгоритмов проявки и не читает приватные структуры сессии по смещениям.
Оригинальные 115 библиотек и 830 файлов данных сохранены без изменений.

## Что добавлено в 0.4.0

- Каталог: импорт нескольких оригиналов, поиск по имени/иерархическим тегам,
  фильтры по минимальной оценке, отклонённым кадрам и пяти независимым цветовым
  меткам; сортировки по имени, оценке и последней обработке; множественный выбор.
- Оценки 0–5, отклонение, цветовые метки и редактируемый список тегов записываются
  публичными API darktable и сохраняются в родном XMP. При повторном открытии
  восстанавливается точный RDF-список: штатный импортёр этой ревизии обрезает тег
  на запятой. Исправление находится в мобильном восстановлении, не в pixelpipe.
  Метаданные снимков обработки восстанавливаются вместе с обработкой.
- Очередь экспорта выбранных фотографий: отдельный XMP и настройки кодировщика
  фиксируются при добавлении. Неоткрытые фото явно используют штатные camera
  defaults. Один дополнительный оригинал копируется в scratch для обработки;
  нет одновременной загрузки всей пачки RAW. Имя результата уникально, после
  записи в SAF проверяется SHA-256 повторным чтением.
- Ошибка отдельного кадра не выбрасывает остальные. Есть остановка, продолжение
  ожидающих и явный повтор ошибочных/прерванных задач. Задачи и результаты
  сохраняются на устройстве. Очередь не является foreground-service: держите
  приложение открытым; после завершения процесса требуется продолжение/повтор.
  При жёстком завершении во время записи в выбранной папке может остаться
  неполный файл. Существующие файлы не перезаписываются и не удаляются.

Каталог доступен через **⋮ → Мои фотографии**, метаданные открытого кадра —
**⋮ → Оценка, метки и теги**, задания — **⋮ → Очередь экспорта**. Для выбора
кодировщика очереди сначала откройте хотя бы одну фотографию. Прежние функции
0.3.0 сохранены. Это следующий этап переноса, не полное соответствие desktop.

## Что добавлено в 0.5.0: рабочая среда desktop

- **Световой стол** теперь основное место отбора: сетка настоящих фотографий,
  поиск, оценки, цветовые метки, сортировка, множественный выбор и пакетный экспорт.
  Один тап выбирает кадр; двойной тап или «Править» открывает его в редакторе.
  Системная миниатюра ещё не обработанного RAW помечается «Исходник».
- **Тёмная комната**: история слева, крупная фотография в центре, инструменты
  справа и лента кадров снизу. На смартфоне история/инструменты сворачиваются
  и занимают нижнюю часть; фотография остаётся видимой. Разделитель меняет
  размеры; переключатели панелей и полноэкранный просмотр освобождают место.
- Список инструментов стал инспектором: выбранный модуль раскрыт, остальные
  доступны ниже и через каталог/поиск. Все прежние параметры, диапазоны,
  числовые черновики и специальные редакторы сохранены. Исправлено
  перехватывание нажатий прокрученными ползунками под закреплённой навигацией.
- **История слева** читает native XMP, а не только мобильное кольцо Undo.
  Можно перейти к шагу или исходной обработке и вернуться к более позднему.
  Полный стек и положение курсора сохраняются отдельно: исходный importer при
  позиции 0 пересоздаёт defaults и иначе теряет будущие строки. Реальное новое
  редактирование начинает ветку; именованные снимки остаются резервной копией.
- **⋮ у выбранного инструмента → Пресеты**: заводские пресеты этого модуля
  экспортирует `dt_presets_list_stored` / `dt_presets_save_to_file`; доступен
  побайтовый импорт/экспорт `.dtpreset` и сохранение текущего состояния.
  Параметры и переносимые маски применяет исходный движок стилей; его native
  миграция масок выполняется до проверки независимости других экземпляров.
  Ограничения камеры показываются для справки; автоматическое применение
  импортированных пресетов не включается. Непереносимые пиксельные маски
  блокируют сохранение, чтобы не потерять их молча.
- Копирование настроек в новый экземпляр и переименование. Экземпляр и порядок
  создаёт native API; XMP переносит неизменённые непрозрачные processing blobs.
  Маски сохраняют native-ссылки, а не становятся автоматически независимыми
  копиями общих форм. Удаление и перестановка экземпляров ещё не перенесены.
- Создание `.dtstyle` позволяет выбрать конкретные состояния инструментов и
  включить порядок обработки. Для сохранения актуальных общих масок состояние
  подготавливается в отдельном native-контексте; открытый редактор не меняется.
  Применение стиля/пресета сохраняет резервный снимок и открывает новую сессию.

Это Android-реализация рабочей схемы darktable, а не запуск GTK-интерфейса на
телефоне. Не добавлены фиктивные вкладки карты, печати или tethering.

| Автопикеры | Прежний тоновый sampler и native-автодействия | Не все desktop WB/Filmic/AgX/levels/patch acquisition перенесены |
| Lighttable-каталог | Импорт пачки, оценки/отклонение, пять меток, иерархические теги, поиск/отбор/сортировка и множественный выбор | Нет всех desktop-правил коллекций, группировки, виртуальных копий, географии, полного metadata editor и синхронизации desktop SQLite |
| GPU/OpenCL и AI | Не включены в существующем Android runtime | Добавление кнопки их не включит; нужны другая native-сборка и проверенные Android backend/драйверы |
| Дополнительные кодеки | Прежний состав runtime | HEIF/AVIF/rendered JXL/EXR/WebP/JPEG2000 отключены; XCF — только экспорт |

Полного равенства с настольной версией пока нет. Строки «нет» и «ещё не» в этой
матрице остаются открытыми задачами, а не обозначаются выполненными из-за нового UI.

## Проверки и ограничения

Для 0.4.0 дополнительно проверяются XMP-каталог и изолированный batch-контекст
на JPEG/NEF/RAF; точные результаты принадлежат отчёту этой версии. Числа ниже
относятся к завершённой квалификации 0.3.0 и не заменяют новый прогон.

Инвентаризация `tools/audit-desktop-surface.py --stage /path/to/runtime`
перечисляет шесть настольных представлений, 47 panel/tool targets,
97 IOP targets и 14 экспортных плагинов закреплённой ревизии. Имена берутся
из CMake с учётом aliases; повторный conditional target считается один раз.
`useless` — шаблон IOP, исключённый из CMake. Наличие SO не означает,
что перенесены все GUI-жесты, pickers и зависимости. Реестр не выдаёт число
исходников за число всех действий desktop и не присваивает 100% покрытия.

Реальный JNI-тест на Linux сохранил JPEG, NEF и 26-МП RAF с экспозицией и
круговой маской, полностью завершил JVM, затем открыл XMP в другом процессе:
на всех трёх файлах пиксели предпросмотра совпали побайтово. Для этих же типов
пройдены native-создание .dtstyle, импорт, применение и повторное открытие.
Проверен Unicode-путь XMP и отклонение неизвестного исходника. Результаты —
`save-result.json`, `restore-result.json`, `style-result.json` в архиве проверки.

Всего пройдены 24 native-фазы XMP/стилей на трёх входах, включая отмену
старого контекста, append/replace и ошибку записи после изменения базы. Передача
контекста сохранила пиксели и не вызвала прежних GLib-critical сообщений о
повторной регистрации типов на этих сценариях. После ошибки восстановился
сохранённый XMP, а не частично применённый стиль.

В ещё трёх сценариях экспортированы и независимо декодированы PNG: одинаковое
состояние до/после передачи XMP-контекста дало побайтово равные RGB-пиксели;
экспорт применённого стиля совпал с его независимым применением к отдельному
оригиналу. Стиль изменил реальные экспортные пиксели. Это не утверждение
совпадения быстрого preview с высококачественным export: прежнее различие
этих двух маршрутов остаётся.

Отдельно выполнены пять применений настоящих встроенных файлов: пример
насыщенности на RGB/NEF/RAF, Nikon D700 на NEF этой камеры и Fujifilm X-T3 на
RAF этой камеры. Все пять изменили пиксели. Автотест каталога подтверждает
наличие всех 534 файлов; каждый из 534 вариантов на каждом типе изображения
не проверялся. Все файлы банка совпадают с оригинальным APK побайтово.

Финальный набор: по 312 Android/JVM-проверок в Debug и Release без ошибок и
пропусков; из них 234 штатных host-теста и 78 device-компонентных сценариев,
адаптированных для Robolectric. На Android instrumentation они не выполнялись.
39 Python-проверок runtime пройдены. Release APK и test APK собраны. Lint:
0 ошибок, 32 предупреждения и 3 информационных замечания. Подпись, ZIP CRC,
16-КБ выравнивание и неизменность original runtime проверены отдельно.

Это выполнение исходного JNI-моста/движка для Linux, не запуск ARM64-библиотеки
на Android. Новый мост отдельно собран NDK для ARM64/API 26 с 16-КБ выравниванием
и `--no-undefined`; все символы разрешены оригинальным Android runtime.
Проверки хранения, XML, стилей, гистограммы, Compose-экранов и готового APK
перечислены с точными результатами в прилагаемом отчёте сборки.

Сохраняется выявленное ранее различие preview/export; это не исправлялось
подменой цветовой математики. Не проверены физический телефон, реальный process
death Android, OEM SAF/IME, скорость, память и длительные сессии. Старые проверки
0.2.1 описаны отдельно в [отчёте 0.2.1](https://github.com/komarpunk-design/Spektrakrill/releases/download/darkroom-mobile-v0.2.1/REPORT-RU.md).
Обычная смена фото теперь сохраняет runtime через передачу контекста. Полная
повторная инициализация после закрытия последней сессии в живом процессе
остаётся границей проверки: прежние GLib-warning пути не объявляются полностью
устранёнными. Retry сохранённого проекта использует его постоянный оригинал,
даже если доступ к прежнему внешнему URI больше не действует.

## Совместимость со стабильным desktop 5.6.2

Прямой запуск официального CLI с XMP нашего движка на JPEG/NEF/RAF завершился
экспортом PNG, но во всех трёх случаях desktop сообщил `mask version mismatch:
history is 7, darktable is 6` и пропустил маски. Нулевой код возврата здесь
не считается успешной совместимостью. Журналы и структурированный результат
`official-desktop-compatibility.json` включены в отчёт проверки.

Это различие форматов версий: masks v7 увеличивает групповой элемент с 16 до
240 байт, добавляет маркеры, операторы и refinement. Простая смена номера на 6
потеряла бы данные или исказила результат. Обратный переписыватель не выдаётся
за проверенную native-функцию. Приложение сохраняет полный родной v7 и заранее
показывает границу совместимости при экспорте XMP и новых blend-v15 стилей.
Обычные штатные .dtstyle остаются исходными файлами desktop 5.6.2.

Для переноса редактируемого v7 нужен desktop с совместимым форматом 5.8+;
для передачи готовой фотографии доступны прежние PNG/TIFF/JPEG. Совпадение
обработки между 5.6.2 и development-веткой 5.8 не заявляется.

## Сборка

Команда `tools/prepare-upstream-runtime.py` теперь восстанавливает исходный
runtime и собирает дополнительный мост. Если исходный runtime уже подготовлен:

```sh
python3 android/tools/build-desktop-bridge.py --stage /absolute/original-stage \
  --ndk /absolute/ndk --output /absolute/new-desktop-stage
cd android
./gradlew :app:testDevDebugUnitTest :app:testDevReleaseUnitTest \
  :app:assembleDevRelease :app:lintDevRelease \
  -PdarktableRuntimeStage=/absolute/new-desktop-stage
```

Путь stage обязан быть новым и находиться вне исходного stage. CI выполняет
тот же дополнительный шаг после сборки оригинального engine. Код и существующие
релизы Spektrafilm не заменяются.
